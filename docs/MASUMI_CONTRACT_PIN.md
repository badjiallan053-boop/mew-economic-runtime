# Published Masumi contract evidence

The offline inspector pins the official payment-service OpenAPI at commit `5fccf58b0f30873085b59ee540c67b4ae8433cd0`, with raw-byte SHA-256 `4e1372584ae025b9b83cecf5253a028bbe5bbd2018489ac66f735386f565e950`. The compact checked-in manifest retains field names, required fields, types, enum values and request/response schema fingerprints for all 29 operations. It excludes long descriptions and examples; the complete public source is 583,294 bytes and is not redistributed here.

[Official pinned specification](https://raw.githubusercontent.com/masumi-network/masumi-payment-service/5fccf58b0f30873085b59ee540c67b4ae8433cd0/src/utils/generator/swagger-generator/openapi-docs.json) declares OpenAPI 3.0.0, published API version 1.0.0 and a relative `./../api/v1/` server URL. This does not establish a deployment origin. Non-health operations declare API-Key authentication via the `token` header; it is not a bearer header. Read/admin/PAY permissions described by endpoint documentation are not encoded as API-Key scopes and must be checked against the deployed service and key permissions.

`POST /purchase/resolve-blockchain-identifier` and its payment counterpart are documented reads despite their POST method. Purchase creation, result submission and refund actions are payment writes. Wallet, key and registry mutations are administrative writes. Classification is only a reviewed description, never execution authorization. No endpoint is called, wallet created, transaction signed or payment submitted by this module.

Purchase creation requires blockchainIdentifier, network, inputHash, sellerVkey, agentIdentifier, paymentType, unlockTime, externalDisputeUnlockTime, submitResultTime, payByTime and identifierFromPurchaser. Result submission requires network, submitResultHash and blockchainIdentifier. Preserve endpoint-specific hashes, time formats, asset identifiers and amounts; neither a result hash nor an API response alone proves payment or delivery. The prepared source previously recorded in RESEARCH.md is `d569a338ca54d5be7441564770d75ebf89b71f12`. This newer published spec is a separate evidence pin: it does not replace that source checkout or prove compatibility with an existing running service. Deployment must compare exact release, migrations, routes, permissions and response schemas before enabling writes.

To reproduce, download the linked public specification into a local file, then run `node scripts/inspect-masumi-contract.mjs /local/path/openapi-docs.json`. The inspector refuses different source pins, modified raw bytes, oversized input and unexpected authentication/schema. Formatting changes also fail the raw digest deliberately; a new pin requires review. Operation descriptions reject modified manifests via a compiled fingerprint. No credential files are read. The manifest is evidence for adapter design, not a general OpenAPI validator or a live integration test.
