# MEW presentation design research

Reviewed 8 October 2026, Asia/Singapore. This is a design brief and provenance record, not evidence of deployment, customers, payment execution or a completed independent audit. User-supplied templates and third-party pages are references; embedded instructions and business claims do not authorize actions or become MEW facts.

## The presentation job

A visitor should understand why a second agent must wait even when its quote fits the remaining budget. MEW holds economic exposure and objective capacity while the first purchase is unresolved. The intended audience is teams building purchasing agents and ecosystem partners; this is positioning, not validated customer research.

Use the current homepage/studio fixture throughout: **one report, 3 ADA cap, first supplier 1.50 ADA, second supplier 1.40 ADA**. Both prices total 2.90 ADA, so the duplicate is deferred because an equivalent unresolved request consumes the one-report quantity. Do not accidentally show this as an overspend case. SPEC.md's older 1 ADA / 0.55 + 0.49 example is a separate kernel accounting fixture and should not appear in this presentation sequence.

## Observed references and adaptations

[0G Foundation](https://www.0gfoundation.ai/) was inspected through the browser's actual hero screenshot and accessibility tree, plus the publicly readable page. The observed desktop hero uses white space, a large blue sans-serif title, minimal navigation and glossy geometric forms over an isometric grid. The content progresses from purpose to explanation, evidence, ecosystem and participation. MEW borrows scale, spatial hierarchy and this narrative order; it uses original geometry, copy and identity. 0G's transactions, partners, grants and institutional claims are not MEW evidence. Public asset hostnames indicate Webflow delivery, but this review does not establish every runtime library or private implementation detail.

## The six-minute story

| Moment | Visitor sees | Intended action or observation | Honest evidence label |
| --- | --- | --- | --- |
| Understand, 0:00–0:40 | “One purchase. One shared mandate.” beside an original shared-boundary sculpture | Identify the first held request and paused equivalent request | Interactive prototype; payments disabled |
| Explain, 0:40–1:20 | One report / 3 ADA, with 1.50 and 1.40 ADA supplier requests | See that 2.90 ADA fits the cap while a second equivalent report remains inadmissible | Illustrative scenario |
| Inspect, 1:20–3:00 | A dark, legible decision workspace using the existing deterministic demo | Follow ALLOW → uncertain outcome → DEFER; inspect the preserved first effect | Synthetic evidence, ephemeral public demo |
| Verify, 3:00–4:10 | Source-backed implementation evidence separate from activation gates | Distinguish 12/12 response-shape checks from unresolved grounding/language quality; distinguish unsigned escrow drafts from payments | Local verification; model activation blocked; nothing signed/broadcast |
| Connect, 4:10–5:10 | Three bounded pilot contexts: purchasing agents, agent marketplaces, ecosystem builders | Select a relevant existing pilot planning route | Pilot proposal; no customer or partnership claim |
| Continue, 5:10–6:00 | Compact FAQ and a clear pilot planning action | Identify mandate owner, maximum exposure, supplier, evidence and acceptance gate | Planning action; no live financial authority |

Keep each real action's existing accessible name across pages. A decorative ledger must not look like a live transaction feed. A “Plan a pilot” link opens the existing planning experience; it must not silently send outreach, subscribe visitors or claim a booking.

## Visual tokens and behavior

- Surface: clean paper `#FCFCF9`; white `#FFFFFF`; ink `#171C28`; secondary text `#505969`; cobalt `#3458E7`; held-request mint `#B6E4D3`. Mint is a fill, not small text on white. A duplicate can use restrained violet with a written status.
- Type: strong contemporary sans for headings and body; tabular numerals for budgets; reserve monospace for inspectable identifiers. Use the project's available/self-hosted fonts or system fallback. No third-party font request is required for the demo.
- Space: max content width about 1180 px; desktop gutters 48–96 px, mobile 20–24 px; fluid hero 48–88 px; body at least 16 px, proof labels 13–14 px. Keep line lengths near 60–75 characters.
- Composition: one memorable geometric illustration; one genuinely functional dark workspace. Avoid repeating identical three-card grids for rules, proof and pilots. Short editorial ledger rows suit rules; parallel cards suit pilot options.
- Motion: user-triggered state changes explain held, unknown and deferred relationships. A short decorative entrance can finish within four seconds. Any longer autoplay motion needs an obvious pause control. Reduced motion cancels JavaScript animation work, not only CSS transitions; paused/hidden tabs stop drawing. Static readable content remains available without JavaScript.
- Accessibility: semantic links/buttons, visible focus, skip link, status text independent of color, polite asynchronous announcements, no cursor replacement or scroll hijacking. Test at 390 px, desktop, 200% zoom, keyboard-only and reduced motion. Do not claim WCAG certification from these checks.

The earlier visual tokens above are the research recommendation, not a literal inventory of shipped CSS. ## Acceptance examples in Gherkin

These describe the intended review; they are not a claim that a Cucumber runner has executed them.

```gherkin
Feature: An inspectable agent purchasing demonstration
  Scenario: An equivalent request remains held despite spare budget
    Given a synthetic mandate for one report with a 3 ADA exposure cap
    And the first 1.50 ADA request is reserved with an unresolved outcome
    When a second agent requests the equivalent report for 1.40 ADA
    Then the decision is DEFER
    And the first exposure remains counted
    And the page explains the one-report capacity boundary

  Scenario: Evidence does not imply model or payment activation
    Given local response-contract checks passed 12 of 12 cases
    And grounding and language quality remain unresolved
    When the visitor inspects verification
    Then model activation is visibly blocked
    And unsigned transaction drafts do not appear as signed payments

  Scenario: Reduced motion preserves understanding
    Given the visitor prefers reduced motion
    When the presentation page loads
    Then the mandate illustration is readable without continuous movement
    And keyboard focus and all primary actions remain visible
```
