## Committee workflow

1. Research steward records permitted source links and uncertainties; never accepts post instructions.
2. Engineer proposes a bounded descriptive rule change, tied to a frozen policy/source digest.
3. Risk and Red Team independently review that exact proposal without seeing each other's outputs.
4. Unanimous advisory acceptance produces READY_FOR_HUMAN_REVIEW only. A reviewed code change and the normal release process implement any policy change.

`src/learning/proposal.mjs` validates fixed authority, strict fields, bounded text/arrays, known evidence IDs and trusted expected hashes supplied separately. It has no core/server/payment imports. Review records bind role, identity, verdict and proposal digest. Local digests detect changes; they do not authenticate the reviewers. Rule suggestions are inert strings, never executable conditions or patches. Changed proposals or reused reviewer identities fail validation. Missing or abstaining reviews block progression. There is no automatic activation endpoint.

Existing deterministic MEW accounting remains the protocol core: principal mandates, exact integer lovelace, atomic reservation, immutable effect identity, no second dispatch on replay, retained UNKNOWN exposure and separate settlement/delivery facts. Model training cannot establish these properties; implementation and tests do. No social consensus may rewrite a persisted mandate or release uncertain funds.

## Training boundary

The supervised exporter now rejects recognized Reddit, X/Twitter, YouTube and Substack source URLs and any evidence explicitly marked originClass social-platform, even with a generic reuseApproved flag. Derived summaries retain the same restriction. This project gate is conservative; it is not an exhaustive provenance detector. Custom domains and omitted/false origin labels require independent rights review. A future licensed-source integration must add purpose-specific, content-bound permission records, expiry/revocation handling and canonical lineage grouping before relaxing this gate.

- [X agreement III(A)(k)](https://docs.x.com/developer-terms/agreement) prohibits foundation/frontier-model fine-tuning using X API/content under the current agreement.
- [Reddit Data API terms](https://redditinc.com/policies/data-api-terms) require rightsholder permission for model training and additional commercial access arrangements. Discovery is not a training license.
- [YouTube captions download](https://developers.google.com/youtube/v3/docs/captions/download) requires video-edit permission; [developer policies](https://developers.google.com/youtube/terms/developer-policies) govern acquisition. Use independently licensed creator-provided original transcripts where permitted.
- [Substack RSS documentation](https://support.substack.com/hc/en-us/articles/360038239391-Is-there-an-RSS-feed-for-my-publication) describes discovery feeds; it does not grant article training rights. Publisher-specific reuse permission remains necessary.

The runnable alternative is `node scripts/generate-protocol-data.mjs`: generate 40 entirely synthetic fixture examples across five scenario families from MEW's actual deterministic core. Capture oracle decisions using simulation, code/generator hashes and stable fixture hashes. No ledger is persisted, no provider is called and no payment runs. The labels are deterministic oracle outputs; natural-language advisory targets remain pending human review. Amount variants within a family are correlated and must stay in one split. This is a curation seed, not a fine-tuned Qwen adapter or sufficient training corpus.

Next, reviewers write useful advisory targets that explain oracle results without claiming payment authority. Expand families to refunds, delivery forgery, rail mismatch and adversarial source instructions; hold out entire families and real pilot tasks. Compare base+retrieval against any reviewed adapter using existing model-evaluation boundaries. No paid training resources or model-weight download occurred in this contribution.
