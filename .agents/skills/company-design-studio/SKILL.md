# Company design engineering studio

Read AGENTS.md, docs/WEBSITE_STUDIO.md and relevant API contracts. Define one accountable author and distinct review questions. This procedure grants no model, publication, wallet or customer-data authority.

1. Establish audience, observable outcome, evidence class and approved design tokens before authoring.
2. Review storyboard and rendered result in two rounds. Keep navigation, mobile mandate context, keyboard focus and motion consistent.
3. Preserve exact backend identities and economic invariants. Decorative role selection never changes ledger state.
4. Save only nonconfidential demonstration briefs through the bounded studio endpoint. Use expectedRevision; reconcile stale or unknown saves by reading the original record.
5. Treat deterministic critiques as reminders and limited heuristics, not independent model judgment or safety approval.
6. Label source code, hosted observations, synthetic examples and proposed pilots separately.
7. Validate failure paths, run the complete regression/build, record the deployed/source distinction and unresolved gates.
