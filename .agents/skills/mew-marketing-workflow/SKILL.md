# MEW marketing workflow

Read AGENTS.md and docs/MARKETING_CAMPAIGN.md. For website work also inspect
public/marketing.html, public/campaign.js and docs/PRODUCT_MARKETING_CONTEXT.md.
This is a host planning skill, not an activated supplier model or account connector.

## Make the connection clear

Clipping produces campaign assets; advertising distributes them. Explain one
recording → five clips → exact-file review → separately approved distribution.
MEW tracks the purchase commitments and their evidence. It does not infer arbitrary
request equivalence, adjudicate rights, edit video or establish marketing lift.

Use one customer-owned source, one agreed bundle, a revision allowance, a human
acceptance owner and a known supplier quote. Show which work is demonstration,
which requires a connection and which is a proposal. The existing campaign uses
one five-outline bundle, 8 ADA A, 6 ADA B, 10 ADA limit; no real media or views.
The homepage's one-report example has different amounts. Do not merge them.

## Bounded agent handoffs

- Planner: audience/offer hypothesis and the proposed deliverable contract.
- Producer: clip candidates, source time ranges, file versions and actual cost.
- Reviewer: exact artifact acceptance, claim/rights gaps and bounded revisions.
- Measurement: account/post/clip identity, window, metric definitions and uncertainty.

Pass structured IDs and evidence references between these responsibilities.
A reviewer must inspect the source/actual output rather than inherit the producer's
approval. Prompt output is advisory; the trusted host controls admission and
financial transitions. These responsibilities do not imply that any model ran.

Keep production fees, ad spend and creator compensation separately typed. Do not
combine fiat, ADA and USDM or imply campaign-wide enforcement across unrelated
objectives. A timeout cannot release capacity or justify dispatching a replacement.
Views, delivery acceptance and payment settlement are different facts.

## Build and verify

Use a GSD-inspired phase record: capture the desired visitor/customer outcome,
plan the bounded change, implement, verify observable behavior, then report the
source/deployment distinction. Read .planning/phases/01-marketing-story for this
release's acceptance conditions; do not treat earlier checkboxes as current proof.

For UI work use native buttons, links and disclosure controls; label examples
beside the graphic; inspect narrow screens, keyboard access, loading/failure and
reduced motion. Check each next-step link. For a real pilot, consent/source rights,
actual output and costs must be recorded before reporting customer results.

Produce: the clear story, proposed contracts/connections, measurable acceptance
criteria, observed verification and remaining blockers. This skill grants no
publishing, ad-account access, payment, credential or deployment authority.
